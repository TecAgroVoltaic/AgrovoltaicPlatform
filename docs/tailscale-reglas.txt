==========================================================================
  LO QUE EL BUILDER "Add rule" NO CUBRE
  (se edita en el editor de texto de la policy, no en el formulario)
==========================================================================

  1) ELIMINAR la regla por defecto "todos -> todos":
        { "src": ["*"], "dst": ["*"], "ip": ["*"] }        <-- BORRAR
     (si no la borras, Cartago queda expuesto a TODOS y la Regla 2 sobra)

  2) Declarar los duenos de los tags (seccion aparte "tagOwners"):
        "tagOwners": {
          "tag:cartago-iot":     ["autogroup:admin"],
          "tag:agrovoltaic-etl": ["autogroup:admin"]
        }


==========================================================================
  DESPUES de guardar la policy  (pasos fuera de Tailscale admin)
==========================================================================

  [ ] Cartago: taguear el nodo (re-auth; tambien apaga expiracion de key y DNS)
        sudo tailscale up --advertise-tags=tag:cartago-iot --accept-dns=false

  [ ] EC2: al crear/instalar Tailscale, meterlo con
        sudo tailscale up --advertise-tags=tag:agrovoltaic-etl

  [ ] Cartago: el servicio debe escuchar en la IP 100.x (no solo 127.0.0.1);
      si hay ufw activo, permitir el puerto en la interfaz tailscale0.

  [ ] Postgres: el "solo lectura" REAL = crear un rol con solo SELECT
      (NO usar el superusuario 'postgres'). La ACL NO distingue SELECT de INSERT.

  [ ] Secretos: auth key de Tailscale y credenciales de BD en gestor de
      secretos, nunca en .env en claro.
