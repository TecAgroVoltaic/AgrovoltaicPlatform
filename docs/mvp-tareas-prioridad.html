Automatizar la ingesta AgroDash → store (frescura de datos)

Impacto altoEsfuerzo SPor confirmar en EC2
Descripción El pronóstico usa como "ahora" el último timestamp del store, no el reloj de pared. El forecast-refresh.timer recrea el contenedor del forecaster para recargar esa serie desde el store.
Problema La ingesta python -m pronostico.etl (AgroDash → store) solo se corre a mano: no hay .timer ni cron en el repo. Si el store no se refresca, el forecaster queda congelado y cualquier demo "en vivo" muestra datos viejos.
